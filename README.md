# 拾忆 · Shiyi Memory 0.16.15

## 当前版本：稳定保存，按剧情召回

本节说明当前版本的默认行为，后文历史版本说明用于追溯。模型速度和漏记情况受服务、正文及配置影响，单次成功不代表永久保证；设备测试也不代表覆盖所有品牌手机。

- **记录 → 总结预设**：可编辑真实总提示词、九模块规则和各模块追加要求，附填写示例与发送预览。支持复制、改名、删除、恢复推荐、JSON 导入导出；“保存并启用”后全局生效，手动与自动总结共用，不增加模型调用，运行中的批次不受编辑影响。
- 人物知情有明确事件关联时，可本地补入相关背景速览；笼统的“知道这件事”用明确关联解释指代，同事件只带一次。无关联不猜测，删除或隐藏记录不重新注入。背景不扩大角色知情范围，注入日志可查看来源与额外体积。
- 手机悬浮窗拖动按帧更新；日志进度不再重建整页，隐藏页面停止无关刷新，记忆列表只替换发生变化的卡片。键盘避让、聊天隔离及人物完整档案保留。

- 正常整批一次主总结，后台进行。可选分工、复核及独立合并会增加调用，界面和日志分别计数；不会为了省略的辅助字段无限重试。实际可容纳楼数取决于正文长度和用户输入预算，不承诺任意长度都一次完成。
- 兼容完整九模块回答的单对象外层数组；缺失辅助获知渠道、获知时间或人物情境时明确标为未注明，不再因此拒绝整批。人设变化未给适用范围时，只保留来源场景的观察，禁止外推成长期人设。缺失来源、人物、知情状态或明确无效的字段仍会报错，不编造剧情补齐。
- 相关人物全部已保存且允许注入的信息完整带入；历史事件由字典、关键词、标签、可选向量和重排按需选择。不同时间、知情范围或有效期不能只因相似而合并。召回不调用聊天模型做压缩，也不等待后台总结。
- 明确记录且有来源的别称会用于字典检索，即使模型未填写事实性质。原记录仍保留“未确认”标记；推测、否认、删除和用户停用的别称不会因此启用，别称不赋予角色额外知情。
- 原文补充先排除人物称呼再匹配主题，避免人名与连接词的碎片误中无关楼层、挤占事件篇幅。身份检索与完整人物档案不受影响；不增加 API 调用或注入上限。
- 模型误把原文短语填入片段编号时，仅在指定楼层唯一、未拆分且短语在该楼原文中唯一精确出现时，按同一原楼层绑定并记录警告；不会跨楼猜测或跳过版本、校验值冲突。
- 事件引用额外带“回忆部分”等文字备注时，只有同一未拆分来源已有独立整楼摘要定位，才改用该完整原楼依据并记录兼容警告；不把备注当真实片段，也不据此补齐缺失楼层。实际分片与版本/校验冲突仍拒绝。
- 完整回答后重复输出的同名空区块不再抹掉已生成内容；只保留唯一非空数组，遇到两份非空或嵌套字段冲突仍报错，不自行拼接答案。日志会说明本地兼容次数。
- 默认不额外开启分工总结、自动合并、自动校对或双次复核；更新不覆盖已有用户配置。按次计费用户可使用记录偏好中的“按次计费：减少额外调用”，并检查复核开关。
- API 和 Key、通用设置与知识库全局保存；故事记忆、来源、自动进度与批次按聊天隔离。不需要另装记忆服务器或连接 Tailscale；自行配置的 API 地址必须能从设备访问。

### 开始使用

1. **API**：配置总结服务并测试连接；向量与重排按需启用，默认地址为 `https://api.siliconflow.cn/v1`，Key 自行填写。地址永不自动补 `/v1`。
2. **记录 → 手动总结**：选择最近楼数或起止范围，再设置每批楼数。一条消息就是一楼。
3. **记录 → 自动总结**：单独设置起点、每批楼数和保留最近楼数，启用后从连续已完成位置接续；打开老聊天不会自行跑完全部历史。
4. **记忆**：查看事件经过、逐楼纪要和人物档案；修改人物时可增减任意属性。自定义区块可手动创建或交给助手提出方案，确认后应用。
5. **召回**：校正字典、管理向量、预览召回并查看逐次注入日志。向量失败可“重试全部未完成”，不需要重新总结。
6. **记录 → 总结批次 / 运行日志**：按楼层管理、批量删除、重生或继续未完成。继续会复用仍有效的已返回结果；重生成功前保留旧记忆。

### 边界

总结是有来源的概括，不保证每个细节都提取。关键状态、否认与知情限制仍须核对；相似措辞不等于同一事件。真实服务可能超时或限流，失败信息与降级会显示，不算作成功。

聊天备份目前只有导出，没有 UI 内导入/恢复；设置与区块的导入导出不等于完整聊天灾难恢复。Android 系统挂起或结束 TT 时不能保证后台继续运行。移动浏览器模拟通过不等于 Android 真机、真实 MVU 卡或 Git 升级验收通过。

## 历史版本说明（不作为当前默认设置依据）

### 0.16.2 候选版：不丢失独立知情与动态属性

- 已提取但没有事件关联的知情记录也可以按主题独立召回，并出现在来源完全一致的楼层下；不会据此生成事件关联，也不扩散到所有参与者。不适当关联被隔离的知情仍能独立检索。手动隐藏、删除和模块开关继续生效。
- 人物属性校对的去重纳入生效时间、截至时间、适用情境和事实性质；相同属性后来再次变化回原值不会被误删。
- 针对真实回答缺陷补充提取要求：条件期限不擅自换算成午夜，跨楼约定完成必须引用实际完成楼，关键关系边界原话需保留为台词证据。这部分新规则尚待实际服务复测，不声称提示词能保证语义正确。
- 真实 LUNA 的0.16.1扁平格式测试已一次请求保存20楼及九模块；保留原始回答作为回归，没有手改回答。该次从模型任务发出到收到结果约4分55秒，且人工检查仍发现事件日期、条件期限和完成状态来源不准确，不能声称已达到1–2分钟或内容全部合格。

这仍是本地候选，不是全功能实机验收合格版。真实 Gemini、向量/重排、助手、知识库分析及 Android 更新流程尚未完成联机验收；不要求用户用真实聊天反复找错。

### 0.16.1 候选版：扁平提取与属性知情校对

- 正常单次总结改为九个并列模块，不再在逐楼记录里层层嵌套变化和知情数组。楼号、非事件记录编号和覆盖信息由本地按来源绑定；仍完整校验逐楼覆盖，不替模型补剧情。已有存储、旧格式响应和检查点保持兼容。
- 提取规则区分“看见某件物品”和“知道物品包含的秘密”，明确逐楼当前时间与回忆旧事时间；人物动态字段沿用原名，只记录新增/变化，不把反复确认另造属性。
- 校对可直接关联人物属性的知情者，不再强迫挂到剧情事件；保留同一知识从不知情到后来知道的状态和时间变化，不把它们误去重。
- 新增20/30/50楼九模块全流程、写盘失败后重开复用响应、跨聊天隔离、同范围重生失败保护、批量删除和恢复后的召回回归。

0.16.0的真实LUNA测试出现JSON格式错误，未作为成功结果；0.16.1随后一次请求保存成功，但速度和内容质量没有全部达标。模拟测试不能证明Gemini耗时、线上向量/重排质量或Android实机全部通过。

### 0.16.0 候选版：一次提取，本地归档

- 默认单次总结使用紧凑返回格式：逐楼纪要中同时记录本楼的属性、知情、关系等变化，程序归入现有九个模块；减少重复抄写来源、编号和覆盖清单。不减少纪要正文，不自动增加子模型请求。20/30/50 楼仍由用户选择，实际请求是否分段取决于输入预算和现有分工设置。
- 属性的知情者可以直接关联该属性，不必硬挂到某个剧情事件。保留任意 DIY 字段及原始数据类型、用户设置、旧总结和旧检查点；人物档案仍完整注入，不设独立人物篇幅上限。
- 本地补充正文明确写出的昵称，保留字典手动覆盖与重名保护。兼容旧模型把属性有效期写在 `temporal` 内的情况；不将叙述转述当成逐字台词。
- 不再由一个人名展开其全部经历主题。过滤缺少当前主题依据的本地候选；语义命中、重排结果与相关事件依赖仍保留。有来源的冲突和核实结论可作为“核对参考”召回，完整保留否认和限定，不把争议当既定事实。
- 缺少同楼或主题依据的知情—事件关联暂不随该事件注入，原知情记录不删除、不重写；注入日志显示隔离数量。运行日志显示本地归档楼数及模块数，结构输入估算按实际发送格式记录。

**验收边界：**这版先作为本地候选，真实模型复测通过前不自动发布。固定的旧 LUNA 回答用于程序回归，不等于新格式的真实模型测试；漏写的人物属性不会从旧备份凭空补出来。单次成功率、1–2 分钟总结目标、Android 网络时延与竞品表现仍需独立实测，不由模拟测试承诺。

### 0.15.0 后台总结，不拖住聊天

- 自动总结不再阻塞 TT 的回复完成事件。手动或自动总结等待模型期间，可以继续聊天；未完成结果不进入召回，使用已经保存的有效记忆。
- 取消隐藏的 46,000 输入限制，直接遵守“总结输入预算”。整批容得下就一次请求；超出配置预算、开启分工或恢复旧的分段任务时，仍可能多次调用，进度栏会显示原因和次数。没有擅自改动用户预算或回复上限。
- 新增批次发布时保留上一份完整记忆视图供本轮召回使用；删除、替换、改楼、切聊天与设置变化仍阻止过期结果注入。时间、知情/明确不知情、全量相关人物档案和 DIY 模块不为提速而裁掉。
- 老聊天只处理目标楼层和已引用来源的正文；新回复仍在生成时也可以整理更早的楼层。模型输入不再重复携带本机校验散列，存档校验仍完整。
- 日志增加首次请求准备、模型等待、记忆发布耗时及历史读取数量；合并短时间内的写盘操作，不合并或丢弃日志条目。强制退出可能丢失尚未写盘的尾部日志（合并窗口 100ms），导出和任务结束强制写盘并核对。
- 更新不会删除聊天、Key、记忆、字典或向量。旧的未完成任务继续原有检查点；想使用新的整批计划，需要对相应批次选择“重新生成”，这会重新调用模型，成功前保留旧的有效结果。

性能目标是总结后台运行、正常召回通常几秒；不靠强制三秒截断来伪装提速。自动测试包含模拟慢模型、移动宿主接口、并发发送及长楼层，但不等同于真实模型成功率、Android 实机时延或竞品速度排名。

### 0.14.2 修复总结前的来源误判

- 修复 0.14.1 长批次在发送模型请求前误报“聊天来源已变化”的问题。读取正文、冻结请求、提交记忆使用同一份来源计划；真正修改原文或切换聊天仍会中止旧任务。
- 旧版失败批次可以直接点 **记录 → 总结批次 → 继续未完成**，不需要删除再总结。已完成片段和已返回结果会按检查点复用。
- 原文读取故障、聊天切换、正文变化及计划不一致分别记入日志；运行中重复点续跑不会另开请求。TT 首页已确认没有聊天时不再误报后台错误。
- 不改变 API、Key、预算、分工开关、聊天记忆、召回及人物全量注入。新增应用级故障注入及官方 TT 历史接口回归；模拟结果不等同于真实模型或 Android 实机验收。

### 0.14.1 总结少等待、失败可续跑

- 默认单次模式先检查完整请求：能容纳所选一批楼层，就一次提取全部区块；确实超出用户预算或安全容量时才分段，不在后台强制把正常一批变成多个付费请求。容量检查完全本地执行。
- 超大批次尽量合并可容纳的片段，完整保留所选正文、逐楼校验和回复上限。进度与日志显示预计及实际请求次数；重试、可选分工、向量请求分别记录。
- 请求计划随任务冻结，失败后使用批次的“重试/继续”复用已完成内容。更新前未完成的任务仍用原分段续跑；新建任务采用新计划。
- 恢复前台时检查是否已超时，避免继续等待被延后的计时器；日志增加实际等待和计时器延迟。系统挂起或结束应用期间不能保证后台执行。
- 不清空已有记忆，不改 API、Key、输入/回复上限或分工设置，不要求重新总结或重建向量。真实模型质量、网关稳定性与 Android 实机耗时仍需实际任务验收，不能由合成测试保证。

### 0.14.0 少调用、精确带入与批次编号

- 新安装默认每个内部片段一次主总结，所有区块一起提取。两阶段分工、自动追加合并核对和自动校对改为可选；长输入拆段与失败补救仍会增加请求，不承诺任意楼数永远只调用一次。
- **已有配置不会被覆盖。** 按次计费用户可在 **记录 → 手动总结 → 共同记录偏好 → 按次计费：减少额外调用** 一键关闭这三项额外调用，不改 API、楼数、回复上限或记忆。关闭后跨批合并候选仍需在“事件合并”中确认/重试，不能把待核对说成已经合并。
- 历史事件使用字典、标签、全文关键词和可选向量/重排覆盖全库，不因年代或楼层久远排除。明确问某件事时，只匹配到同一人名的本地无关候选不再填满余量；宽泛续写、语义命中、已重排候选及明确事件关联不受该规则过滤。DIY 字典、扩展区块和人物完整档案继续保留。
- 注入在本地将明确关联同一事件且边界一致的条目归组，共同时间、地点、知情等说明只写一次，独有内容保留。不同时间/知情视角不合并，不修改原记忆，不增加压缩模型调用。逐次注入日志显示省掉的重复行和字符，以及未选中原因。
- 批次按当前有效楼层范围连续显示编号；删除、重试不会继续消耗展示序号。永久记录 ID 不变，筛选分页不重新编号，自动总结仍按连续已保存的实际楼层接续。
- 新增合成回归：2000 条后续记忆中找回第 23 楼旧事、别称/标签/语义独立命中、10/20/30 楼单次正常路径、字符预算和时间/知情边界。测试不代表真实模型、Android 设备或网络延迟的保证，也不构成与 ANIMA/SPV 的性能排名。

### 0.13.0 分工总结与阶段续跑

- 默认分工总结：第一阶段由总结模型整理完整事件、关键台词与逐楼摘要；第二阶段根据原文和事件编号整理知情、人物、关系、人设、约定、演绎及 DIY 属性。正常每个内部片段两次请求；合并、校对或必要纠错另计。
- **API → 辅助整理模型**默认沿用总结地址和 Key。只要选一个辅助模型，就能在同一服务商下使用快速模型；留空则继续使用总结模型，也可关闭“沿用总结连接”使用独立服务商。
- 用户选择的 10、20、30 楼均按实际楼层管理。超长正文在批次内部拆段；已完成阶段暂存到当前聊天，点击原批次“重试”复用成功阶段。不要用“重新生成”替代续跑。
- 相关旧记忆按内容筛选，去掉重复存储凭证和校对引文，不再按巨大预算填充历史。后台校对请求过大时按记录拆组，新总结优先；校对失败不撤销已保存总结。
- 模型复用临时编号不会让后续楼层覆盖先前摘要。事件引用错误只修对应引用，不能靠删记录或抹掉来源来通过校验。
- 运行日志分开显示正文、旧记忆、结构约束、衔接内容的长度估算，并保留服务端报告的真实 Token 数；这两种数值不是同一单位。
- 不改变已有 API、回复上限、聊天记忆、人物全量注入及自动开关。记录偏好可关闭“分工总结”使用单次模式。分工不保证两次调用一定比一次快，实际耗时取决于模型、原文和服务商；可为辅助整理选择快速模型。

为 TauriTavern 整理聊天记忆，完整带入相关人物档案、按当前剧情召回历史事件，并用自然语言配置记录方式。设置、助手和资料库保存在 TT 全局扩展存储，故事记忆按聊天隔离，不需要部署 Anima Remote 或额外的记忆服务器。

面向 **Android 与 Windows 的 TauriTavern 2.2.0 或更新版本**，通过 Git 安装、检查更新，不需要重装 TT。手机工作台接入 TT 的安全区域和键盘避让，导出使用 TT 原生文件接口。

已在官方 Windows 便携版验证总结保存、助手应用、聊天请求注入及暂停；Android 适配有窄屏和宿主接口测试，**尚未在 Android 实机完成端到端验收**。测试使用虚构聊天，不代表真实模型的记忆质量保证。

### 0.12.2 失败恢复与移动端总结稳定性

- 每个源楼层子批次独立计算恢复与补全次数；前一批的超时不会耗尽后续批次的恢复机会。
- 120000 等较高输入预算仍可保存，但移动端总结会自动限制单次源材料规模，避免生成 8 万以上的超大请求；超大单楼仍按原文片段无损拆分。
- 502/超时后的恢复请求会先移除无关历史上下文，并在不修改用户设置的前提下使用本批合理的临时回复上限；运行日志记录压缩前后大小与实际上限。
- 总结界面会明确显示“压缩无关历史后重试”，缓存故障仍不会冒充总结失败。

### 0.12.1 失败恢复与移动端总结稳定性

- 恢复缓存或缓存目录索引写入失败时，不再阻断正式总结；有效模型结果仍按权威记忆存储校验并保存，缓存问题只进入运行日志。
- 单个区块校对兼容常见的非空数组返回；校对按条目保留有效证据，错误条目单独待重试，不再让一条错误证据拖掉整组。
- 超时/连接失败最多自动恢复一次，避免移动端因重复等待长时间卡住；502 等短暂服务错误仍保留有限重试。
- 日志继续区分缓存警告、模型失败、校验失败与持久化失败，方便判断是服务问题还是插件问题。

### 0.12.0 内容校对、字典补齐与故事时间

旧记忆无需清空或全部重新总结。打开对应聊天，在 **记忆 → 内容校对 → 校对／重试未完成** 中核对已有记录；仍使用总结 API。只处理未核对、失败或内容已变化的组。每组一次独立请求，遵守总结输入预算、回复上限和超时，不无限重试，也不在聊天召回时调用。

默认开启“总结后校对缺项与矛盾”：新总结先保存，再对检测到的知情覆盖、时间解析、部分关系过度解读和跨模块住址矛盾候选核对原文。没有检测到候选不代表内容毫无遗漏；已核对也不等于模型不会判断错。可关闭自动校对，保留手动入口。

每项校正或新增须有对应楼层逐字证据，详细纪要显示校对依据。校对失败保留旧总结，人工确认的属性不被模型覆盖，疑点随对应记录显示和注入。补入的学校、技能或自定义属性归入人物档案，知情按具体事件、内容、渠道和时间记录，不把参与者直接变成全员知情。校对独立保存，可以撤销；删除、重生或修改来源使对应校对失效。聊天备份同时包含原始记录、有效视图与校对资料。

字典补入有依据的简称、称呼和字段检索词，补齐具体主题标签；共享称呼保留歧义，用户校正、停用或删除优先。未提取或无法确认的别称仍需校对或手动添加，不能从通用称呼猜人物身份。新总结提示词加强跨模块检查，避免学校只留在别人知情里、感谢被写成双方确认恋爱。

支持中文日期、同日时间区间和明确起止日期。当前场景日期只读当前聊天最近正文，不从全局设置、现实日期或召回到的未来计划取值；回忆/跳转日期无法区分时保持未确认。日期读取暂时失败不阻断其他有效记忆注入。人物仍全量注入、不加单独上限；向量沿用已有增量更新，不要求重新总结来建索引。

### 0.11.2 完整链路诊断

“记录 → 运行日志”区分主总结与每次补全，显示具体校验字段、请求编号、回复状态、JSON 出错位置与本机保存阶段。向量、重排、助手、知识库、手动管理操作与召回降级共用诊断入口；日志只记录安全结构，不默认保存模型原文、Key 或聊天正文。

每条新日志记录执行版本。保留最近 2000 条、最多 2 MB，超过容量会明确显示清理数量及受影响任务；导出全部保留日志，不受当前分页和筛选影响。旧版本丢失记录、宿主未提供的网络细节或强制退出前未保存记录无法补录。更新不需要重新总结，不改变现有记忆。

### 0.11.1 人物档案全量注入

本轮输入或最近一条 AI 正文明确提及人物名称、无歧义的字典别称时，带入该人物全部已保存且允许注入的属性、对应关系、人设变化、知情记录及人物专属演绎参考，不再只选某项兴趣。自定义属性和已启用注入的 DIY / MVU 字段一并保留。

人物档案没有单独上限，也不占历史记忆的条数和长度额度；不为筛选人物属性增加模型请求。历史事件继续走字典、关键词、可选向量与重排召回。相关设置改为“历史记忆最多注入几条”“历史记忆注入长度上限”。人物内容采用完整已保存文本，不以短摘要代替。

时间、有效期、适用对象与知情范围随记录保留；提及某人不等于此人在场，更不等于全员知道其秘密。内容和条件完全相同的重复事实只带一份，不同有效期或不同自定义字段不会误合并。删除、不再召回、区块关闭仍生效；不凭空补齐未记录的人设，也不会自动灌入所有未提及人物。

注入日志分开显示全量人物数、属性/记录数和历史记忆条数，可查看待发送内容。日志明细的显示容量不限制实际请求。插件移除的是人物注入裁剪，服务商自身上下文限制仍存在。本次不改手机整体布局、不改存储结构；更新后现有档案直接适用，无需重新总结。

### 0.11.0 人物档案、独立自动总结与知识库导入

**记忆 → 人物与事实**按人物归成档案，身份、住址、爱好、能力或任意自定义属性均可纳入。点一次“修改人物”，统一修改属性、增添新属性或勾选移除，一次保存。支持文字、数值及结构化 JSON。扩展模块和 MVU 只读区块仍独立管理，不会被档案修改覆盖。

同一属性的相同取值集中显示，保留每次来源；不同取值作为内容与变化保留，不按聊天楼层先后擅自覆盖历史。档案删除可从回收站逐条恢复。归档是兼容旧数据的显示方式，不需要重新总结，不修改底层原记录；不使用检索别名擅自合并人物身份。

**记录 → 自动总结**与手动总结分开。新聊天从 #1 起算，需要开场白可填 #0。已连续完成 #1–130、每批10楼，下一批是 #131–140；改变每批楼数不会改写历史编号。中间未完成、已删除或来源失效的批次不算连续完成。保留最近楼数单独设置，默认保留2楼；每次自动触发只处理下一完整批，旧聊天不会在打开时悄悄发出几十次请求。可主动“处理下一批”，或用手动范围补齐历史。暂停自动不影响手动总结和注入；暂停插件会暂停全部插件任务。

**召回 → 字典**的“校正”在该条目下展开，带入现有名称、别称、关联词；多个草稿相互独立。别称帮助检索同一对象，关联词扩展相关主题，均不代表人物已经知情。分类策略可选24候选或48候选，重排数量与之对齐；最终注入条数和长度不变，更多候选可能增加接口耗时。通用值是本项目的起始配置，不是质量最优或优于其他插件的证明。

**设置 → 世界与知识库**先选择 TXT / MD / JSON，预览切片，再确认导入。默认600字一段，可调整长度或分隔符。世界书 JSON 只提取已启用条目。关键词索引在本地完成；可选用助手分析资料并生成字典、用向量 API 建索引。所选服务接收解析后的相关文字，不接收文件二进制。原创和同人共用流程，分别标明设定/计划与原作/分支边界。

资料库可逐库启停、预览和删除；分析及向量分别显示进度，失败可继续，不重做总结。新建的资料向量保存在全局存储，各聊天共享；故事记忆仍按聊天隔离。向量页面也计入共享索引。切换向量地址或模型后需建立对应索引；资料卡上的“上次建成”不保证与新模型兼容。仅有关键词索引也能使用资料，不需要开通全部 API。

关系分类、人设及其他区块使用中文说明，保留方向和具体依据。知情记录显示对应角色的获知时间，不再附上互相矛盾的“时间未提取”；人物属性不再机械显示事件时间/地点缺失。关联事件的时间与地点单独注明，人物住址不等于发生地点。

新总结明确要求具体的关系经过及动态属性；旧记录若只保存分类而没有经过，插件不会编造，可修改或重生对应批次补全。0.11.0 曾按属性检索；0.11.1 已改为相关人物全量注入，具体行为见当前版本说明。

### 0.10.0 可靠保存与继续未完成

进入 **记录 → 总结批次**，可用“继续未完成”“继续全部未完成”或选中后继续。继续会复用同一任务已经返回的模型结果和已提交子批；“重新生成”才重新总结整批，新结果成功后再替换旧结果。原文、侧重点或记录规则改变时拒绝复用过期草稿。旧版本没有保存原始响应的失败批次，仍需重新生成。

缺少少数楼层摘要或补充区块必要字段时，只请求补全对应内容，事件和已有摘要不从头重做。临时超时、连接中断、408/429/5xx 与补全共享**每个逻辑批次最多 2 次额外模型调用**；正常每个内部子批 1 次。认证、证书、来源错误和长时间限流不自动反复请求。模型输出截断不会冒充完整结果；调整回复上限或模型后可继续。合并仍是独立任务，其请求数另计。

总结响应先暂存再校验、提交；向量响应先写独立检查点再发布索引。成功提交后仅辅助进度文件失败，不再当成记忆全部丢失。数值记忆、设置与向量保持精确小数；写入回执异常时先读回核实，不盲目重复写入。

运行日志会显示结果暂存、复用、局部补全、重试等待和进度待恢复。日志不含原始回复。总结暂存含原文与模型结果，仅在当前聊天的本机私有任务存档中保存，不进入召回、配置助手或常规备份；续跑有效期 7 天（使用时淘汰过期暂存），每聊天最多 24 份 / 32 MB、单份不超过 8 MB。已完成子批清理响应，向量只保留一个未完成响应检查点。它们不是加密保险箱：整个 TT 数据目录的备份仍可能包含这些文件。磁盘完全不可写、应用被系统强杀前尚未落盘的内容，无法保证重启恢复。

仍严格检查逐楼覆盖、来源、人物与事件关联，不靠删除错误记录或伪造知情者来“提高成功率”。本版没有切换存储后端、引入区块多模型路由，或把十万级索引的性能问题宣称为已解决；大索引仍有整份索引发布开销。

### 0.9.2 向量保存与总结兼容

向量存档保留完整小数精度，并严格读回确认。旧索引和续传检查点继续可用；日志新增具体的本机保存阶段。人设变化没有明确期限时保留为“有效期未确认”，不推定永久变化，不再仅因模型省略期限字段使整批总结失败。

### 向量失败独立重试

进入 **召回 → 向量 → 重试全部未完成**，直接补建当前聊天已保存记忆的向量。成功项跳过，失败、缺失或内容过期的项目继续处理，不调用总结模型。列表可筛选“失败项”，查看中文错误并单条重试；重启后进度仍在。

长记忆分段编码并保留全文，以分段最高相似度参与原有标签、分类和关键词融合。每次请求同时限制片段数量和文字长度；遇到输入批次或序号不兼容，有限拆小请求，不把错误返回关联到另一条记忆。服务整体不可用时暂停队列，等待手动重试，不反复自动请求。全量重建在独立暂存空间完成，保留旧索引直至新索引完整。

**运行日志 → 向量索引** 可看请求条数、输入长度、返回数量、向量维度、成功/待补建数量以及 HTTP 或网络错误，不包含原文、Key 或服务端原始响应。TT 2.2 原生向量后端尚未实现，向量请求由 WebView 直连；模型列表可拉取不等于向量请求一定可达。`network.request_failed` 仍可能来自网络、证书或跨域限制，不能凭此断定哪一种。

### 0.9.0 总结先保存，合并单独处理

跨批事件合并不再作为整批总结保存的前置条件。逐楼摘要、结构和正文来源仍严格校验；合并目标缺失、时间无法对应或合并接口出错时，有效总结和旧记忆保留。

**记录 → 事件合并** 显示当前聊天的合并候选和结果，支持只重试合并、改选目标、保持独立和撤销合并，每页 10 对。缺失目标可搜索当前有效事件重新选择。重试不会重跑整批总结，也不会覆盖原始记录。已失败、尚无总结结果的旧批次仍需在批次管理重试，不能凭错误日志恢复未保存的内容。

“总结后自动合并”默认开启，可在记录偏好中关闭。仅处理总结模型提出的候选，使用已配置的总结 API 逐对判断，**每对增加一次模型请求、每次最多 10 对**，剩余可在合并面板继续。失败或不确定的项目不无限重试。没有合并候选不追加请求；打开聊天、召回和注入不运行合并模型。输入预算、回复上限和认证沿用总结设置。

合并采用可撤销视图：原记录、来源楼层与批次归属保持独立；事件按核对结果展示和检索，正文使用原有经过，不让合并模型重写事实。各片段的时间、状态和知情范围分别保留，不把某人知道一个片段扩大为知道整件事。删除、重生或修改原记录会使对应旧合并关系失效。要修改合并事件，可先撤销合并，再编辑原记录；删除或“不再召回”会作用于该合并视图的所有组成记录。

运行日志增加独立的“事件合并”筛选，能区分模型请求、HTTP 失败、核对结果与保存。内置配置规则同步到 1.1。合并判断仍可能不确定；不同日期的相似经历或事实性质冲突不会强行合为一条。没有扫描全部记忆自动认定相似事件，也不承诺真实模型不会误判。

### 0.8.0 自动索引、内置配置规则与注入日志

总结保存后，从有来源的人物、地点、别称和标签更新自动字典；已启用知识库的分析结果也加入检索字典。进入 **召回 → 字典** 可测试、校正、停用、删除或恢复词条。删除后不会因为下一次总结而自动恢复。词条是检索线索，不是角色在场、知情或事实成立的证据。

**召回 → 向量** 显示当前模型的索引覆盖率。首次使用需填写 API 并开启向量召回；新安装的“后台更新向量索引”默认勾选，此后只更新新增或改变的记忆。可以手动更新、排除/恢复某条索引、打开原记忆修改。向量数值由模型生成，不需要手工编辑；排除向量不影响原记忆及关键词检索。旧用户已保存的开关保持原值。

**召回 → 本轮 → 逐次注入日志** 可看每次经过注入入口的实际片段、来源、字典/标签命中、筛选和耗时。只保存本聊天最近 30 次，单条过大时显示截断提示，存储较大时提前淘汰旧项。写入日志不等待模型请求发送。默认导出只含诊断计数；需要分享正文时另行勾选并确认。它证明拾忆把什么加入了待发送请求，不证明服务器收到，也不能证明模型在输出时采用了这些记忆。

**助手 → 内置配置规则** 展示 8 组指南。可直接点“按内置新手规则配置”，或继续使用导入的 TXT/MD/JSON。规则覆盖全部非密钥配置及现有工具边界，设置清单随程序注册表更新；助手可读取索引与最近注入诊断、提出设置或扩展模块方案，确认应用后生效。批次删除、索引重建等仍通过界面操作，不声称助手已经执行这些动作。

默认每 5 楼一批、总结输入预算 24000、回复上限 8192；字典、标签、分类候选已经配置。API、向量/重排等产生费用的功能与自动运行仍需用户选择。旧用户可在 **设置 → 设置与备份 → 应用推荐记忆参数** 确认采用，不覆盖 API 或记录偏好；自定的大回复上限不被升级重置。

时间表述暂时无法确认一致的合并不再拖垮整批：暂存独立事件并列入“冲突与疑点”，旧记录不改动，不认定事件发生了两次；明确冲突仍拒绝强并。未默认增加多个总结 API，一批仍统一抽取并校验人物、事件、知情和楼层的关联；总结/助手/向量/重排维持各自连接。

### 0.7.1 总结字段自动纠错

已完整返回的总结如果只有枚举状态写法不合规，会先兼容明确等价的中文写法、大小写及空格；不把“未知”默认当成“已知情”或“明确不知情”。仍无法识别时，同一总结模型最多追加一次字段纠错请求，只发送问题记录、关联事件及对应正文，不重做整批，不改正文来源、时间或其它字段。正常总结和本地兼容不增加请求。

纠错仍受已设置的输入预算、API 认证、回复上限和取消控制约束；运行栏及日志显示“正在自动纠正字段”和结果。模型不能确定、来源不符合或再次校验失败时不强行保存，旧成功批次保留。该纠错请求可能产生额外的模型用量；没有无限重试。此功能针对枚举字段，不绕过事件合并、逐楼完整性或来源校验。更新后可在原失败批次重试，无需修改 API 或继续提高回复上限。

### 0.7.0 轻量召回与手机工作台

顶部新增“召回”，下设“概览、字典、向量、策略、注入、本轮”。概览显示实际功能开关、词条与标签数量、索引状态；配置好 API 不等于开启向量，索引完整也不代替 API 连通测试。

“字典”可以测试一句话的别称匹配与标签触发，不调用 API。自动词条来自当前聊天和启用资料，手动校正为全局设置。知识库文件继续在“设置 → 世界与知识库”导入、分析。

“向量”显示当前模型、已索引/总数、待更新数量及可搜索的分页记录列表。开启“向量检索”后，可另行勾选“后台更新索引”，保存后只对新增或内容变化的记忆调用向量 API；默认不勾选，升级不会擅自开始收费请求。后台失败不无限重试，可手动继续。切换聊天取消旧任务，不使用其他聊天的索引；更换模型需要对应的新索引。

“策略”的分类检索在候选阶段执行，能从事件、人物、约定、资料等类别补充相关候选，而不是只重新排列最终结果。关键词、标签和向量候选合并后至多重排一次；同一查询向量复用于各通道，没有逐类额外 LLM 规划。

不想逐项调整，可以点“使用推荐分类策略”，开启字典、标签与分类候选；不会改动 API、向量开关或已有注入上限。实际聊天召回参考最近剧情以补足“她、继续”等查询，详情仍按当前询问选择。修复中文夹数字时混淆编号，以及标签候选预留反而把高分结果排到末尾的问题。

完整纪要与逐楼摘要仍完整保存、索引。注入使用速览及查询相关句段，不再为了用完预算而展开整个事件；日期、知情和后续条件保持关联。明确链接到同一事件、且内容及约束已被本轮选中记录覆盖的摘要不重复注入；没有确切依据或有新细节的记录不强行合并。“本轮”可查看各候选为何选中、为何省略、重复覆盖与分阶段耗时。旧记录没有速览时仍保留原有正文行为，可在原批次重生补齐。

手机端使用紧凑分类条、两行速览和可展开详情，修改/删除收进每条记录的“操作”。九个标准分类即使为零也保留，自定义区块、批次批量管理、独立 API 配置及已保存数据保持不变。

下列旧版本说明记录当时行为；召回与索引的现行方式以 0.7.0 为准。

### 0.6.3 回收站、楼层信息与事件合并修正

批次列表默认只显示未删除的记录。单批或批量删除后立即从当前列表移除，可通过“回收站”查看、恢复；恢复后回到当前批次。删除不影响聊天原文，也不需要清空或迁移旧存档。

楼层摘要新增人物、时间、地点和事件关联的提取要求。已保存摘要可通过明确事件链接，或同一版本的正文来源，显示关联事件已有的时间、地点和知情信息，不调用模型补写。同楼多个事件分别列出，不把事件的全部参与者当成本楼全员在场。知情信息只展示能定位到本楼及此前的记录，后续获知或来源跨度无法确定的知情不会倒填。没有可用字段时显示“本条记录未提取”，不再冒称“原文未明确”；姓名不自动等于知情者。旧记录本身缺少的信息仍需在对应批次重生后补提取。

事件合并识别同一日期的横线、斜线和中文年月日，以及“日期 → 同日具体时分”的精度补充，保留更精确的已有时间。同批第三段可引用前面已经合并的临时事件编号。真实不同的发生时间仍阻止合并；无法解释的时期描述不强行视为一致。日志分别说明目标不在本次上下文、明确时间冲突、时间表述尚不能确认三种原因。失败时旧成功结果保留，不自动重发收费请求；可以在批次管理重试失败批次。

### 0.6.2 自动跟随当前聊天

打开、切换或重新进入聊天时，自动加载该聊天独立的记忆和总结批次；关闭悬浮窗或暂停自动总结、注入，不影响读取。返回首页时清空面板中的上一聊天内容，再进入聊天即可恢复，不需要重新总结。

切换时停止旧聊天任务并清除旧注入，迟到的结果不会写进新聊天。编辑、删除或重新生成正文后会重新核对来源，失效内容不继续召回；原批次仍可查看、删除或重生。正常切换不再反复弹出“重新打开聊天”的红色错误。

API、Key、通用设置、资料库及配置助手对话仍是全局配置，不随聊天重置。自动加载只读取本地数据，不触发模型请求；需要自动总结与注入时再启用相应功能。

### 0.6.1 批次替换、批量管理与事件归并

重复总结同一起止楼层只更新原批次，新结果完整保存后替换旧结果；失败、停止不会清掉上次成功记忆。更新后打开聊天，会整理旧的同范围重复批次，保留最近成功结果，原始历史和整理前目录保存在本地。部分重叠但范围不同的批次不擅自撤下。

在“记录 → 批次管理”勾选批次，可选择本页或全部筛选结果，批量删除、恢复、重生。重生按楼层先后执行；中途停止时已保存部分保留，未完成批次的旧结果保留。删除只撤下记忆，可恢复，不删聊天原文。

同一次事件的跨楼经过合成一条事件卡，模型对既有事件的明确关联经过目标与时间检查，来源楼层、参与者和知情信息一起保留。仅题材相似、不同日期的两次经历不自动当成一件事。人物观念、态度变化和关键原话会显示在完整纪要中，包括说话人、对象与语境；原话核对来源，不要求聊天模型反复引用。旧摘要缺少这些内容时，可多选旧批次重生，不自动消耗模型额度。

### 0.6.0 完整纪要、自动字典与标签召回

同一批总结要求用简体中文同时保存完整事件经过、逐楼摘要和人物等变化。事件纪要保留起因、参与者、时间地点、具体行动与对话、转折和实际结果，不以一句标签代替。另有短的召回速览用于控制注入篇幅，不另发总结请求。标题、完整纪要、召回速览各自保存；列表点击“完整纪要”阅读，来源显示聊天楼层，内部标识不占正文。

在“模块 → 世界与知识库”查看自动字典：来自当前聊天总结及已启用资料库分析，支持词条查询、分页、校正、停用和撤销校正。别称用于识别同一对象；关联检索词只是搜索关联，不能作为同一人物的证明。同名别称有歧义时不会自动归并。手动校正为全局配置，自动词条随当前聊天和资料启用范围变化。TXT / MD / JSON 原文仍按段完整保存；旧资料再次点击“分段分析资料”可补字典。模型返回非结构化结果时保留文字并提示字典待补全。

默认启用自动字典与标签辅助召回。检索读取完整纪要及元数据，关键词候选与语义候选合并；本轮触发的标签各补一组候选（默认每标签 4 条，最多 4 个标签），去重后最多重排一次。查询向量只计算一次并复用于各标签，不追加逐标签 LLM 规划。未配置向量/重排时使用本地关键词检索；关联候选仍需相关性和预算筛选，不是每个标签必定注入。

注入先给所选记忆留出速览及知情、时间等约束的空间，再按剩余预算展开完整经过；全文放不下时可补与查询相关的连续句段，保留相邻语境、不截半句话。在“本轮记忆 → 这次如何找到记忆”查看命中词条、触发标签及使用的检索方式。不将整本字典或全部知识库塞进请求。

修改正文会清除旧速览和该条旧自动词条，避免旧版本继续参与注入；标题、速览和标签可以手改。旧的一句话/英文纪要不能凭空补成完整故事，需要在原批次点击“重新生成”；新结果通过校验并保存成功之前，旧有效结果保留。更新后如索引文本有变化，旧向量会标记过期，需要重新建立向量索引；不自动调用 API 重建，不删除现有记忆或更改用户的回复上限。

本版在合成数据和手机尺寸宿主接口环境中验证，不代表真实模型一定遵从所有要求，也不是 Android 实机效果或云 API 时延保证。

### 0.5.5 总结格式与字段诊断

修正总结提示词中“空数组”的范围：九类记忆使用记录数组，`coverage` 楼层处理情况必须是对象，里面的来源、已处理、未处理等字段才是数组。补全来源引用规则和关系变化选项；模型只需准确引用消息 ID、必要的片段 ID，版本与正文校验信息由插件绑定，不必让模型重复抄写。

`VALIDATION_ERROR` 不再只显示笼统失败。提示及“记录 → 运行日志”会列出区块、记录位置、字段和问题类型，例如 `coverage` 应为对象却收到数组，或 `summaryView[0].sourceRefs[0]` 来源信息不匹配。方括号内是从 0 开始的记录位置，不是聊天楼层号。每个阶段最多展示 24 项，保留总问题数。日志只含固定字段名、类型、问题分类及数量，不保存来源 ID、哈希值、事件名称或原始模型回复；重载、筛选、导出继续有效。

来源不明、来源版本不符、缺楼及真实结构错误仍停止保存，不猜测、不跳过校验、不自动重发收费请求。不改现有回复上限、API、Key、记忆或存储位置。旧版日志只有错误码时，无法追溯当时具体错误字段；新的字段信息从更新后的请求开始记录。

### 0.5.4 运行日志与逐楼摘要检查

在“记录 → 运行日志”查看运行过程，也可点击悬浮窗底部的“日志”。保留本机最近 2000 条、最多 2 MB，按执行版本、任务编号、阶段、批次与楼层显示；支持失败/警告筛选、分页、完整保留记录 JSON 导出和清空。达到容量上限会说明已清理数量和部分保留任务。重载后可以读取已保存日志；清空日志不删除记忆、批次、设置或助手对话。日志单独保存在 TT 全局扩展存储，不含 Key、地址、模型名、聊天正文、附件内容或模型原始回复。每次校验最多保留 512 个具体字段，其余数量明确标注；旧版本缺失的诊断不能补录。

总结日志显示实际发送的 `max_tokens`（设为 0 时显示未发送、沿用服务端默认）、输入估算、响应结束原因、服务报告的 Token 用量、逐楼摘要数量、缺失/重复/空摘要楼层、保存阶段和耗时。服务未提供的用量不猜测。其他操作记录连接测试、模型列表、助手、文件导入、知识库分析、向量建库与手动召回的开始/结果；不记录主聊天正文。

`FLOOR_SUMMARY_MISSING` 表示逐楼摘要没有完整对应输入楼层，不等于回复上限不足。已补全模型格式要求，明确每条用户/角色消息都要有独立摘要，来源 ID 与绝对楼层号不能混用；来源字符串、sources/messageId 等项目原本支持的格式会先安全归一化再检查。真实缺楼、重复、合并多楼或空摘要仍会失败，不按数组顺序猜来源，不拼接正文冒充摘要，也不自动重复收费请求。

只有服务明确报告 `length` 等截断标记时才显示“输出被截断”。已有保存内容保留；失败批次可以从“批次管理”重试。更新前未记录的请求无法事后补录。日志保存失败会明确显示“仅在内存保留”，不影响原有总结存储结果，可以及时导出。

### 0.5.3 TT 聊天存储首次读取

修复首次打开聊天、手动总结或恢复记忆时，TT 连续弹出 `Chat store entry not found` 的问题。TT 2.2 的聊天存储与全局扩展存储接口不同；拾忆先查询当前聊天中自身命名空间的记录，再读取已存在的文件。尚未建立的检查点、总结批次等按空记录处理，不再触发宿主的“文件不存在”通知。

不删除或重建已有数据，不更换存储位置，不修改聊天正文、API 或 Key。权限不足、文件损坏及读写失败仍会报错；不会全局关闭 TT 错误提示。直接更新扩展并重载即可，无需卸载。

### 0.5.2 直接读取当前聊天与范围选择

在 TT 中打开目标对话后，进入“记录”，选好范围直接点“开始总结”。无需先点“开始使用”：每次新手动任务会确认当前聊天，首次使用、重载、换聊天或编辑正文后按需读取和恢复该聊天的记忆。API 配置仍全局共用，不因读取聊天而要求重新填写 Key。进行中的任务遇到换聊天或正文变化仍会停止，不将结果写入另一聊天。

“总结范围”只能选择一种：“最近 N 楼”或“指定起止楼层”。未选中的字段隐藏且禁用，不参与请求；“每多少楼记录一次”只决定分批。例如最后一楼 #20，最近 10 楼、每 5 楼一批，整理 #11–15、#16–20；指定 #1–10、每 5 楼一批，整理 #1–5、#6–10。读取成功后显示实际楼层范围和数量。模型请求和新楼层摘要使用真实聊天楼层编号，不从每批 0 重新计数。

手动总结不自动开启后台整理或聊天注入。“启用自动 / 暂停自动”与手动总结分开；自动任务仍按对应开关执行。确实没有聊天、正文尚未加载、持久存储不可用和读取期间切换聊天会分别提示。已有记忆不自动删除；旧版已存下的错误楼层编号不会在升级时猜测改写，需要修正的批次可使用“重新生成”。

### 0.5.1 Key 保存与记忆管理

在每个模型区域填写 Key 后点击“保存”，Key 会单独保存在当前 TT 的本机数据中，重启后自动恢复；输入框仍为空以免回显，旁边会显示“Key 已保存”。留空保存会保留同地址的旧 Key，替换时输入新 Key，删除时使用“清除已保存 Key”。无 Key 接口仍可留空使用。切换到另一服务地址不会自动带上旧服务的 Key。

四类 Key 均不进入助手消息、配置 JSON、区块定义或拾忆备份。此存储不是操作系统加密钥匙串；TT 整体数据备份可能包含本机 Key，请勿随意分享。不会读取或覆盖酒馆主 API 的 Key。旧版只保留在内存、已经丢失的 Key 无法找回，更新后需重新填写并保存一次。已有记忆独立存储，不因 Key 为空而删除；缺 Key 会影响需要认证的总结、向量、重排或助手请求。

“故事记忆”的九个入口使用统一字号和高度，同级正文保持一致。原“待核对”改名为“冲突与疑点”，用于存放来源矛盾或未确定的内容，不参与自动召回；核实后可在正确区块新增记忆，再删除疑点。

“新增记忆”的区块下拉框包含扩展模块，可选择字段填写。MVU 区块显示为只读并提供读取入口，不允许手动编造变量值。

“记录”分为“总结与自动记录”和“批次管理”。批次不会自动消失，但默认只显示最新一页 10 批，可选择 20 / 50 批、翻页或跳页；支持 #120 查找所在楼层、100-200 查找范围、第3批查找编号，以及侧重点、状态筛选。只有展开批次时才建立详情，关闭的批次不堆满页面；原删除、恢复、重生入口保留。

### 0.5.0 自定义扩展模块

“记忆”页新增默认折叠的 **扩展模块**，九个基础区块保持不变。可以点击“新增区块”，也可以对配置助手说：“新增主角等级区块，从 MVU 读取等级，记录变化。”助手会询问缺少的事项、探测可用变量路径，列出方案，点击“应用并保存”后才生效。已有区块支持修改、删除和恢复；不需要为每种新属性更新插件。

区块有三种来源：

- **随总结记录**：按照区块记录要求，在原有总结请求中提取，不为每个区块单独调用模型；记录保留楼层来源，纳入原有批次的删除、恢复与重生。
- **手动记录**：填写文字、数值或开关，可以修改、删除并从记录页回收站恢复。
- **MVU 只读**：从当前聊天的 MVU 楼层变量选择字段，显示当前值与有采样的楼层历史；同楼刷新不重复记录，重 Roll/正文变化后不把旧来源当成当前事实。找不到变量或读取失败会明确提示，不由 AI 猜测，不修改原 MVU。需要角色卡的 MVU 框架已加载并暴露 getMvuData；不要求另配模型。

一个区块可包含 1–16 个字段。MVU 选择器列出最多 200 个非敏感叶子路径；助手只获取路径和类型，不获取无关变量值。MVU 读取在本地进行，初始化/更新事件、消息到达和发送前会尝试刷新，也可手动点击“读取 MVU 变量”。读取最近 20 楼中的最新有效变量；没有采样过的历史不伪造补齐。按需勾选“参与记忆召回”，使用既有轻量召回预算，不会无条件塞入所有扩展记录。

区块定义全局共用，但手动内容、总结产出和 MVU 快照按聊天隔离。删除区块是归档，可恢复，不删除原始记忆或角色卡变量。区块定义可独立导出 / 导入 JSON 分享给朋友，不含聊天记录、变量值或 Key；同 ID 的不同定义不会静默覆盖。纯配置与全局备份也包含区块定义，聊天备份另含 MVU 快照。配置助手仍每次保留一份待应用方案，多个区块可分次确认。

### 0.4.0 全局设置与总结批次

所有设置在未打开聊天、切换聊天或正文变化后仍可保存。配置助手的对话、方案和附件为全局；故事事实不会跨聊天合并。首次打开旧聊天时仅迁移该聊天尚未建立的全局设置 / 助手 / 资料，不扫描其他聊天，不覆盖已有全局配置，旧存档保留。

“记录”中填写起止楼层和“每多少楼记录一次”。例如 1–300 楼、每 10 楼一批，生成 30 条编号记录。每批可展开查看九类产出和楼层摘要，可删除、恢复、重生；失败或停止保留已完成批次，未完成结果不进入召回。重生成功后才撤下旧结果，失败保留旧记忆。旧版本未记录楼层号的批次可查看和删除，但重新总结需要手动指定范围。

“记忆”始终显示九个区块，空区块也可新增。支持手动修改、删除、回收站恢复；知情记录关联事件。删除是可恢复的逻辑删除，保留原始版本，不删除聊天楼层；其他批次仍有依据的共同事件不会被整条抹除。

预算分为输入与回复，均可修改：总结输入默认 12000 估算单位，助手输入默认 16000；这是输入规划值，并非服务商精确 Token 计数。总结和助手回复默认 4096 Token，实际传入模型请求的 `max_tokens`；回复设 0 时不发送该字段，沿用服务端默认值。模型自己的上下文与输出上限仍生效。旧版保存的输出预留数值会沿用为回复上限，可自行调整。长批次可能按输入预算继续拆小；不会静默跳过楼层。

“设置与备份”可独立导出纯配置、全局资料及助手备份；故事备份仍需选择对应聊天。备份不包含本插件运行期 Key；附件及对话可能含私人信息，请自行保管。

### 0.3.8 API 独立配置

API 页面不绑定聊天：没有打开角色或聊天时，也可保存 API、拉取模型和测试连接。总结、助手、向量、重排的地址、模型、认证方式，以及 API 页的请求设置，保存在 TT 的全局扩展存储，所有聊天共用。修改正文、重 Roll 或切换聊天不会使 API 请求失效；主动停止仍可取消请求。

0.4.0 起，记录 / 注入 / 检索 / 世界设置、助手历史及资料库均为全局。只有故事记忆、总结批次和本轮召回按聊天隔离。首次打开有旧版 API 配置的聊天时，若还没有保存全局连接，会继承旧配置；已有全局连接不会被其他聊天覆盖。旧版 Key 仅保留本次运行；0.5.1 起随 API 保存到本机并自动恢复。

### 0.3.9 连接测试与高级选项

总结与助手的连接测试使用独立的短请求，上限从 16 提高为 512 Token，不改变正式总结预算，也不自动重复请求。收到完整文本时显示测试成功；回复达到上限、只有思考字段、空回复或被服务拦截时，显示黄色提示“服务已响应，但尚未验证完整文本回复”，不误报为网络不通，也不冒充文本生成已通过。认证 / HTTP 错误、超时和无效响应仍显示失败。

“地址与认证”改名为“高级连接选项（通常不用改）”：地址如何使用决定是否自动补资源路径，永不自动补 `/v1`；Key 发送方式默认使用标准 Bearer 请求头，无 Key 的服务可留空或选“无需 Key”。只有服务商明确要求时才选 `x-api-key`。已有设置值保持不变。

连接测试只验证这次短请求；正式总结仍按完整响应和结构化内容校验，截断输出不会因连接测试可达而被标记为保存成功。

### 0.3.7 手机窗口与操作提示

修复 Android 输入法弹出后窗口重复缩小、内容底部被裁切的问题。标题、导航和底部结果栏留在窗口内，表单使用一个滚动区域；无论浏览器缩小视口还是键盘覆盖视口，都按 TT 的稳定视口高度避让一次。

拉取模型列表和测试连接显示进行中及成功 / 失败结果。手动与自动总结显示正在处理的楼层，确认保存后才显示成功；超时、HTTP 错误、格式错误与主动停止分别提示。任务进行中可从底部停止，收起窗口不取消任务；失败时悬浮入口也显示提醒。

### 界面与推荐配置

实际悬浮窗分为“记忆 / 记录 / 助手 / API / 模块”。注入、检索、世界与知识库在“模块”中分别配置；初次打开即显示默认值，加载当前聊天时保留已保存的设置。

向量与重排的新配置预填 `https://api.siliconflow.cn/v1`，模型分别为 `BAAI/bge-m3` 和 `BAAI/bge-reranker-v2-m3`，均可修改。旧配置的空白项可用卡片上的“补齐推荐值”，不会替换已填的自定义服务。推荐依据：[硅基流动向量接口](https://docs.siliconflow.cn/docs/api/embeddings-post)、[重排接口](https://docs.siliconflow.cn/docs/api/rerank-post)。这不是个人账户可用额度或模型质量保证；使用硅基流动需要自己的 Key。

总结 API 由你选择服务商；助手默认沿用总结连接。四类模型支持“拉取模型列表 → 选择”，也能手动填写。列表拉取和连接测试使用表单当前值，但不自动保存；确认后点对应卡片“保存”。标准 `/models` 列表请求通过 TT 原生网络发送，避免 WebView 跨域限制，且只使用当前插件所填认证，不借用主聊天 Key。自定义完整端点可在地址选项填写模型列表地址，该额外地址只保留本次会话；非标准路径或带查询参数的列表地址仍直接访问，需要服务允许跨域。失败不影响手动填写模型。

召回缓存、候选选择及异常提示继续保留，不改变现有数据格式。0.3.6 对齐了基本界面分组；0.4.0 已补齐楼层分批管理；自动字典、完整 MVU 与新版人物分析仍在开发，不包含在本次交付。

关键词索引与向量数据按当前聊天复用，内容变化时更新；首次打开大库仍需要准备时间。候选数量与最终注入条数分开，默认收集 24 条候选，再按原有条数和篇幅限制装包，不缩短历史范围。在线接口失败或向量索引不完整，会在召回预览与本轮注入中显示降级提示。

不设强制三秒总限：“在线总超时保护”默认 0，表示沿用各接口时限；新配置的向量、重排时限各为 4000ms，已保存的设置不会被覆盖。两阶段都耗尽时限时可能接近八秒，另有本地处理开销；超时保护不是正常速度目标或质量保证。已通过 198 项自动化测试，真实聊天质量与 Android 实机体验仍需验证。

## 手机安装与更新

1. 在手机 TT 打开 **扩展 → 安装扩展**。
2. 粘贴以下 Git 地址并安装：

```text
https://github.com/cszgezi-lab/Shiyi-Memory.git
```

3. 按 TT 提示重载页面，点击聊天界面的“拾忆”悬浮按钮。不需要下载 Windows ZIP，也不用部署后端。
4. 后续在 TT 的扩展管理中检查更新、更新拾忆。**等聊天生成及插件任务结束，保存设置，再重载页面**，新版本就会生效。版本号显示在拾忆标题与“模块 → 设置与备份 → 版本与更新”。

仓库启用了 TT 的 `auto_update` 标记；是否自动检查还取决于 TT 的扩展更新设置。这里的更新是“从 Git 更新代码，再重载页面”，不是在进行中的请求里无缝替换代码。不要用卸载再安装来代替更新。记忆、设置与助手历史独立存储，代码更新不主动清理这些数据；Key 仅存内存，重载后需要重填。

若出现 `Failed to prepare Git fetch / An IO error`，是 TT 拉取仓库阶段的问题，还未开始运行插件。先确认手机网络能访问 GitHub，检查安装地址是否完整、TT 版本是否不低于 2.2.0，再重试。无需修改 Anima 服务器或 Token。

如果旧版报“需要 ST 客户端 2.2.0，当前版本 1.18.0”，这是拾忆 0.3.0–0.3.2 的版本声明错误，不是装错 TT。TT 应用版本与扩展加载器的 ST 兼容版本是两套版本号。更新拾忆到 **0.3.3 或以上**并重载即可移除这道错误拦截；不用重装 TT。若扩展未能加载，在扩展管理中对拾忆单独更新，不必先打开拾忆面板。

## 开始使用

1. 点击“拾忆”悬浮按钮。扩展页也保留打开悬浮窗的快捷入口。
2. 在“API → 总结模型”填写 API 地址与 Key，拉取并选择模型（也可直接输入），点“保存”和“测试连接”。这一步不需要打开聊天；不需要鉴权的接口，Key 留空即可。配置好后，在 TT 中打开要整理的聊天。
3. 在“记录”选择“最近 N 楼”或“指定起止楼层”，填写每批楼数，必要时填写侧重点，直接点“开始总结”。一楼就是一条消息：最后一楼为 20，最近楼数填 10 即整理 11–20。
4. 整理成功后在“记忆”查看事件卡，展开“知情、时间与来源”核对内容。在“模块 → 注入 → 查看本轮记忆与召回预览”可预览本地召回，不消耗模型请求。
5. 确认记忆合适后，在“模块 → 注入”开启“自动注入相关记忆”，保存设置，再点“启用自动”。后续聊天会在预算内加入相关记忆。需要后台总结时，另开启“记录”中的自动整理。

重新加载或切换聊天后，自动读取当前对话对应的记忆和总结批次，无需点击“启用自动”或再次总结。需要恢复后台总结、注入时再点“启用自动”；“暂停自动”会停止当前任务和后续自动整理、注入，但仍跟随当前聊天加载记录，不删除数据。API、通用设置、资料及助手历史保持全局；0.5.1 起已保存的 Key 会在重启后恢复，输入框不回显真实 Key，但显示保存状态。修改或重 Roll 正文后，会重新核对记忆来源，旧批次保留供管理，不自动调用模型重生。

“启用自动”本身不会调用模型或整理历史；自动整理、自动注入、向量、重排和外部资料检索默认关闭。

## 配置助手

助手默认使用总结模型的连接和 Key，也可以在“API → 配置助手”关闭“沿用总结模型”，配置独立连接。它不是固定问卷：可以一次描述全部要求，也可以继续追问、修改。

助手读取当前设置的字段、类型和范围，生成变更方案；点击“应用并保存”后，参数才真正生效。所有持久化字段共用严格校验，包括记录偏好、时间、注入预算、向量融合、重排、分类通道策略及各连接的非密钥参数。登记的配置字段均为全局；故事记忆内容仍按聊天隔离。Key 不能由助手读取或写入，不会作为提示词发送给模型。

对话自动保存，可以创建新对话、切换历史或删除当前对话。删除助手对话不会删除记忆或已经应用的设置。在“模块 → 设置与备份”可撤销上次助手配置；若相关字段后来又被修改，会拒绝覆盖这些新修改。

### 按 MD / SKILL 配置

在“模块 → 世界与知识库”把文件用途选为“配置 MD / SKILL / JSON 规则”，选择文件并导入，再到助手点“按导入的规则配置”。助手页也有文件入口。可以先告诉助手自己的角色卡特点、希望保留哪些信息，再要求一次生成方案；有必要信息缺失时仍会询问。

MD、TXT、JSON 会先读取成文字，不作为二进制附件上传。大文件分段分析，进度会保存，可停止后继续；多段分析需要多次模型调用。原文保留供后续读取，但模型生成的压缩笔记仍可能漏掉细节，重要规则应核对方案。单文件上限 20MB，不支持 PDF、EPUB 或图片解析。

## 怎样记录与召回

- 一次能够容纳的总结批次，由一个总结模型共同提取事件、知情变化、人物事实、关系变化、人设变化、约定、演绎参考、摘要视图和冲突。不是让九个模型逐块调用。
- 每条记录带来源；事件和知情、时间信息一起打包。没有证据的知情者或日期，不自动当成确定事实。
- 可以直接在“记一件事”补充设定和知情者，不需要模型调用。它属于用户确认的记事。
- 默认用本地中文 BM25 检索，并按预算选择少量记忆。向量与重排是可选增强，失败时回退本地结果并显示降级提示；开启它们会增加网络等待和费用。未启用在线能力与已启用但运行失败分别处理。
- “分类通道策略”是本地类别均衡或 memory / knowledge 通道选择，不是跨设备同步、远程分片或多节点数据库。
- 修改、删除或切换原聊天消息后，旧注入会暂停。重新打开当前聊天会校验来源；必要时重新整理修改的范围。未能验证的来源不会悄悄当成有效。

手动明确范围从 0 开始，单次最多 200 条消息。总结和召回预算是保守估算单位，不是提供商的精确 token 数。某条记忆连同知情与时间信息装不下时会跳过，不会只留下裸事件。

自动整理在回复完成后检查新增消息数量，处理最近配置数量的消息。开启前已有的长篇历史、停用期间积累的更多楼层，需要手动选择范围补整理；不是自动回填全部历史。

## 人物、日期与外部状态

可以保存身份、地点、关系和有来源的人设变化，但不能保证模型永不 OOC，也不会强制控制剧情走向。人物称呼支持每行 `主名=别名,别名`，无需维护复杂词典。

“当前故事日期”使用 `YYYY-MM-DD`，未知可留空，不会把电脑日期当故事日期。已记录的约定时间、原定时间和实际发生时间会分别展示；“昨天 / 前天”根据你设置的当前故事日期计算。剧情跳日后需要更新该日期，本版不保证自动识别所有时间推进。

外部状态只读路径限定为宿主公开的 `chatMetadata` 或最后一条消息的 `lastMessageExtra`，例如你的宿主确实暴露对应字段时可填写 `chatMetadata.stat_data`。这不是文件路径，也不是完整 MVU/EJS 集成：本版不会重写变量系统、角色卡、预设或世界书。

“同人”模式把原作作为参考，当前聊天的分支事实优先；没有自动分析整本书并生成完整可编辑主线图的承诺。原创世界也可导入文字资料。启用“检索外部资料”后，资料才参与召回；配置规则与世界资料用途分开。

## API 地址与故障

- 基础地址模式只补资源路径：总结/助手补 `/chat/completions`，向量补 `/embeddings`，重排补 `/rerank`。**永不自动补 `/v1`**。
- 完整端点模式按所填地址使用；已有资源路径不会重复拼接。
- 支持无需认证、Bearer 和 x-api-key。Key 是否必需由提供商决定，插件不强制要求非空。
- 标准 `/chat/completions` 和 `/models` 通过 TT 的原生网络发送；带查询参数或非标准路径的完整端点、向量和重排推理目前直接由 WebView 访问，需要目标服务允许跨域。不能保证所有“兼容 OpenAI”接口都支持。
- 手机上的 `127.0.0.1` / `localhost` 指手机自己，不是你的电脑或服务器。填写手机实际可访问的模型服务地址，优先 HTTPS；私人内网服务要先接通对应网络。不同 Android 构建对明文 HTTP 的限制需实测。
- 测试连接成功只说明短请求成功。大文件、工具调用、输出截断或上游超时仍可能失败。可以减少总结范围、分段分析、提高合理的请求截止时间，或选择支持工具调用与结构化 JSON 的模型。

“本轮 → 最近一次请求准备”表示记忆已经加入宿主待发送请求，不等于服务器已收到。暂停后不会继续为新请求注入。建议避免多个记忆插件同时注入相同内容；拾忆不会替你关闭其他插件。

## 分享与数据

朋友使用同一个公开 Git 安装地址，在自己的 TT 和聊天中配置自己的 API 即可。**不需要你的 Anima Token，也不需要登录你的 Tailscale 账号**。如果使用的模型 API 本身位于私人网络，则另行获得那个 API 的访问权限。

公开仓库只有插件代码、说明与校验清单，没有开发者聊天、模型 Key、导入作品或测试环境。不要给朋友发送自己的 TT `data` 目录、完整聊天备份或隔离测试目录。

如果曾经手动复制过本地版，先禁用旧的手动副本，再从 Git 安装；不要同时启用两份拾忆。不要删除聊天数据。新安装使用相同的插件存储命名空间；其他设备不会因此自动同步你的记忆。

手机导出会调用 TT 的原生导出流程，可能保存在 Downloads 或显示系统文件选择器。备份会包含私人内容，请留意存放位置。

“导出纯配置”不含记忆、附件、助手历史或 Key，但会包含你填写的 API 地址和偏好文字，分享前仍需检查。“导出当前聊天备份”含当前聊天的插件记忆、资料和助手数据，应私人保管。**本版只有导出，没有 UI 内导入/恢复备份功能；不能把它当作已验证的完整恢复方案。**

## 开发与验证

安装后的扩展运行于 TT，不需要 Node、Docker 或独立记忆服务。运行时没有第三方 npm / CDN 依赖；导出时使用 TT 自带的 `/scripts/file-export.js`，布局和存储使用宿主接口。

本仓库是可直接安装的运行源码，正式入口为根目录 `index.js`。测试工具、报告和测试宿主不发布到安装仓库。核心保存采用不可变数据块、清单、提交指针和写后校验；失败候选不等于已提交记忆。

适配依据：[TT 2.2.0 布局契约](https://github.com/Darkatse/TauriTavern/blob/v2.2.0/docs/API/Layout.md)、[原生文件导出](https://github.com/Darkatse/TauriTavern/blob/v2.2.0/src/scripts/file-export.js)、[扩展安装与更新](https://github.com/Darkatse/TauriTavern/blob/v2.2.0/src/scripts/extensions.js)。

独立 API 配置使用 [TT 全局扩展存储](https://github.com/Darkatse/TauriTavern/blob/v2.2.0/docs/API/Extension.md)，不使用当前聊天的存储句柄。
